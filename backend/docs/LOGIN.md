# ล็อกอินด้วยอีเมลมหาวิทยาลัย

- `POST /auth/login` รับ `email` และ `password` ตรวจโดเมน `rmutp.ac.th` แบบตรงตัว
  แล้วตรวจรหัสผ่านกับ scrypt hash และ `email_verified_at` จากฐานข้อมูล
- ไม่รับ Gmail, subdomain หรือชื่อโดเมนที่เพียงมีข้อความ `rmutp.ac.th` อยู่ข้างใน
- รหัสผิดกับบัญชีที่ไม่มีอยู่คืน `invalid_credentials` เหมือนกัน
- บัญชีที่รหัสถูกแต่ยังไม่ยืนยันอีเมลคืน `email_not_verified` และไม่สร้าง session
- ล็อกอินสำเร็จคืน `token`, `expiresAt` และ `user` (id, name, role)
  ไม่มีอีเมลหรือ password hash ในข้อมูลผู้ใช้ที่ส่งกลับ
- Token สุ่ม 32 bytes อายุ 24 ชั่วโมง ฐานข้อมูลเก็บเพียง SHA-256 digest ในตาราง
  `sessions` ที่มีอยู่แล้ว ไม่ต้องสร้างตารางใหม่
- `GET /auth/session` ตรวจ `Authorization: Bearer <token>` กับฐานข้อมูล
- `POST /auth/logout` ลบ session ของ token นั้นโดยตรง ทำซ้ำได้
- API ที่เพิ่มในอนาคตต้องตรวจ session และบทบาทที่ Backend ก่อนอ่าน/แก้ข้อมูลส่วนตัว
  การซ่อนหน้าจอหรือปุ่มในแอปไม่ใช่การอนุญาตสิทธิ์

## แอป

หน้าเข้าสู่ระบบเรียก Backend แทนการเปิดฟีดโดยตรง ยืนยัน OTP สำเร็จจะลองล็อกอิน
ด้วยรหัสผ่านที่ผู้ใช้เพิ่งตั้ง ถ้าทำไม่ได้จะกลับหน้าล็อกอินพร้อมข้อความให้ลองใหม่

Token อยู่ในหน่วยความจำของแอปเท่านั้น ไม่บันทึกลง localStorage หรือไฟล์
รีโหลดหน้าเว็บหรือปิดแอปแล้วต้องล็อกอินใหม่ เมื่อครบอายุแอปจะล้าง session
การออกจากระบบล้างข้อมูลในเครื่องและเรียก Backend เพื่อเพิกถอน token
ถ้าเครือข่ายขาดระหว่างออกจากระบบ token ฝั่งเซิร์ฟเวอร์จะหมดอายุเองภายใน 24 ชั่วโมง

เว็บในเครื่องใช้ `http://127.0.0.1:3001` โดยปริยาย และ Android Emulator ใช้
`http://10.0.2.2:3001` ในโหมดพัฒนา มือถือจริงและ production ต้องกำหนด
`EXPO_PUBLIC_API_URL` ให้เป็น Backend ที่เข้าถึงได้ ใช้ HTTPS บน production

## การจำกัดคำขอ

จำกัด 20 ครั้งต่ออีเมล และ 100 ครั้งต่อ IP ภายในช่วง 15 นาที
นับทั้งครั้งสำเร็จและไม่สำเร็จ โดยอีเมลถูกเก็บเป็นแฮชในตัวนับ
จำกัด scrypt พร้อมกันสูงสุด 4 งานและขนาดตัวนับสูงสุด 10,000 รายการต่อ process
ไม่เชื่อ `X-Forwarded-For` จาก client โดยตรง

ตัวนับนี้อยู่ในหน่วยความจำ เริ่มใหม่เมื่อ restart และไม่แชร์ข้าม instance
ก่อนขยายหลาย instance ควรใช้ตัวนับกลางและกำหนด trusted proxy อย่างชัดเจน
แถว session ที่หมดอายุจะใช้ไม่ได้ทันที แต่ยังต้องตั้งงานล้างแถวเก่าเป็นระยะเมื่อ deploy

## การทดสอบ

```powershell
npm.cmd --prefix backend test
```

ทดสอบฐานข้อมูลจริงจากโฟลเดอร์ `backend` โดยใช้ `.env` ของเครื่อง:

```powershell
$env:RUN_AUTH_DB_TESTS = 'true'
node --env-file-if-exists=.env --test tests/login.integration.test.mjs
Remove-Item Env:RUN_AUTH_DB_TESTS
```

Integration test สร้างบัญชีชื่อสุ่มสำหรับทดสอบ ยืนยันบัญชีนั้นในฐานข้อมูลเพื่อทดสอบ
เงื่อนไขล็อกอินโดยไม่ส่งอีเมล แล้วลบเฉพาะบัญชีและโควต้าที่การทดสอบสร้างขึ้น
ไม่ได้ใช้บัญชีจริงของผู้ใช้และไม่ได้เปลี่ยนโครงสร้างฐานข้อมูล
